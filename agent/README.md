# EpiGuard — كاشف المعلومات المضللة في الصحة العامة

هذه هي النسخة الأساسية للمشروع. تستقبل شائعة أو ادعاءً صحيًا، وتتحقق منه
من مصادر طبية معتمدة، ثم تعرض الأدلة والحكم بدرجة تحفظ مناسبة.

نظام تحقق صحي يعمل بجد، مش مجرد قواعد ثابتة ولا ملف تعليمات. دورة كاملة:

```
Sense → Plan → Act (tools) → Verify (طريقتان) → Remember
```

## التشغيل المحلي

```
py agent/agent.py "هل المضاد الحيوي يعالج كورونا؟"       # ادعاء صحي، مع إنترنت
py agent/agent.py --chat                                 # محادثة تفاعلية
py agent/server.py                                       # شاشة الشات: http://127.0.0.1:8733/
py -m unittest discover -s agent/tests -p "test*.py" -v
```

التحقق من الادعاءات الطبية يستخدم الإنترنت ومصادر معتمدة افتراضيًا. هذا هو
مصدر الحقيقة في المنتج، لا قاعدة معرفة داخلية. يمكن تعطيل البحث الحي في
تشغيل سطر الأوامر فقط باستخدام `--no-web`. إذا تعذر الوصول للشبكة أو لم
تكفِ الأدلة، يرجع النظام `unverified` ولا يخمّن.

ملاحظة: مجلد `junior-academy/public-health-rumor-lab/` هو مشروع تعليمي
منفصل، ولا يُستخدم في الحكم النهائي أو كـ source of truth في المنتج. الحكم
النهائي يأتي فقط من المصادر الحية WHO/CDC/NIH ومواقع طبية رسمية أخرى.

من مجلد المشروع الأب شغّل شاشة الويب:

```text
py agent/server.py
```

ثم افتح `http://127.0.0.1:8733/`.

للتشغيل على عنوان/منصة نشر:

```text
py agent/server.py --host 0.0.0.0 --port 7860 --no-browser
```

يقرأ الخادم متغير البيئة `PORT` تلقائياً عند عدم تمرير `--port`.
لبيئات الحاويات التي تملك health checks استخدم:

```text
GET /healthz
GET /readyz
```

كلاهما يعيد `{"status":"ok"}` بدون تشغيل بحث خارجي. ويمكن تعطيل تسخين
الكاش عند بدء التشغيل باستخدام `--no-warm-cache`.

## البنية

- `agent/agent.py` — حلقة التحقق الصحي وتوجيه الادعاءات.
- `agent/tools.py` — الجلب والبحث وتحليل الأدلة الصحية.
- `agent/server.py` — خادم HTTP وواجهة المحادثة والجلسات.
- `agent/web/` — واجهة المتصفح.
- `agent/tests/` — اختبارات الادعاءات الصحية، مقاومة الحقن والضغط، والتحقق الحي.
- `agent/benchmarks/` — مجموعة تقييم مستقلة صغيرة قابلة للتكرار، لا تستخدم
  الإنترنت أثناء القياس، وتفصل حالات الخطر العالي.
- `junior-academy/public-health-rumor-lab/` — قاعدة المعرفة ومحرك الشائعات الصحية.
- `Dockerfile` — صورة النشر التي تشغل `agent/server.py`.

المشروع يعتمد على مكتبات Python القياسية فقط، لذلك لا يحتاج إلى `pip install`.

## الخصوصية والحماية

- لا يسجل الخادم عنوان IP في سجلات المحادثة.
- الجلسة قابلة للحذف عبر `DELETE /api/history?session=<id>`.
- يمكن معرفة سياسة الاحتفاظ عبر `GET /api/privacy`.
- يوجد حد 20 طلبًا في الدقيقة لكل عنوان اتصال على واجهة الخادم.
- يمكن ضبطه عبر `EPIGUARD_RATE_LIMIT`. كما توجد حدود افتراضية لحجم JSON
  (`EPIGUARD_MAX_BODY_BYTES`) ونص الادعاء (`EPIGUARD_MAX_TEXT_CHARS`) لمنع
  استنزاف الذاكرة والطلبات.
- يضيف الخادم رؤوس `nosniff` و`DENY` و`no-referrer` لكل رد.
- زر «الحكم ده غلط» يحفظ ملاحظات المراجعة في `agent/feedback.jsonl`
  لتحسين قاعدة المعرفة بمراجعة بشرية.
- feedback لا يدرّب النظام تلقائياً. تصدير بيانات التدريب لا يقبل إلا الصفوف
  التي يضيف لها المراجع البشري `reviewed=true` و`accepted=true` ووسماً صريحاً
  (`rumor` أو `supported` أو `unverified`) لمنع تسميم بيانات التدريب.
- توجد بوابة أمان قبل البحث: النفي المركب يعيد `unverified`، ونصائح إيقاف
  أو تغيير الأدوية لا تتحول إلى `supported` من نتائج البحث أو النموذج، بل
  تطلب الرجوع إلى طبيب أو صيدلي.
- توجد بوابة طوارئ منفصلة لعلامات الخطر الواضحة مثل ألم الصدر الشديد،
  صعوبة التنفس، فقدان الوعي، النزيف الشديد وعلامات السكتة؛ لا تنتظر بحث
  الإنترنت في هذه الحالات واتصل بخدمات الطوارئ المحلية.
- لا توجد معالجة صور مدمجة حاليًا؛ OCR يحتاج محرك صور مستقلًا، وسيُضاف
  كطبقة إدخال منفصلة بدل خلطه بمنطق التحقق.

## ماذا يفعل

| الوضع | الأداة | التحقق |
|---|---|---|
| `rumor` | بحث حي في WHO/CDC/NIH ومصادر معتمدة | أدلة مؤيدة ومعارضة + مصدر الحكم |
| `web` | جلب رابط طبي حقيقي | فشل الجلب = إفصاح صريح، لا تخمين |
| `unverified` | الأدلة غير كافية أو الإنترنت غير متاح | الامتناع عن الحكم القطعي |
| `clarify` | النص ليس ادعاءً صحيًا واضحًا | يطلب ادعاءً صحيًا بدل الهلوسة |

## الصدق المدمج

- يوجد دعم اختياري لبعض backends عند توفير مفاتيحها في بيئة التشغيل، لكن
  غيابها لا يحول النظام إلى إجابة تخمينية: التحقق المحلي والويب والامتناع
  تظل هي المسارات الآمنة.

## البيانات والخصوصية

- `agent/conversations/` قد يحفظ جلسات الواجهة محليًا أثناء التشغيل.
- ملفات الكاش والسجلات لا تدخل في منطق الحكم.
- هذه الملفات ناتجة عن التشغيل وليست جزءاً من منطق التطبيق، ويجب عدم
  رفعها أو تضمينها في صورة النشر.

## الحدود الصحية

الحكم الصحي هو تحقق تعليمي من ادعاء ومصادر، وليس تشخيصاً أو بديلاً عن
طبيب. عند عدم كفاية الدليل يعيد النظام `unverified` بدلاً من اختلاق حكم.
لا ينبغي استخدامه وحده لاتخاذ قرار علاجي أو إيقاف دواء، حتى عندما يعرض
مصدرًا موثوقًا؛ راجع المصدر نفسه ومختصًا صحيًا.

## مسار التعلم الآمن

بعد مراجعة `agent/feedback.jsonl` يدويًا، يمكن استخدام
`feedback_learning.export_reviewed_training_data` لتوليد JSONL نظيف للتقييم
أو لتجهيز ضبط نموذج لاحقًا. لا يغيّر هذا الملف الحكم الحي مباشرة؛ يجب تشغيل
اختبارات التقييم ومراجعة المصادر الطبية أولًا.

لتشغيل benchmark المحلي:

```text
py agent/benchmarks/run_benchmark.py
```

النتيجة لا تدّعي دقة طبية شاملة؛ هي قياس انحدار للسلامة والتصنيف على أمثلة
لم تدخل في مسار تشغيل الويب، وتفشل العملية إذا ظهر خطأ في حالة عالية الخطورة.
